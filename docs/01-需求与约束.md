## 一、项目目标

做一个 Windows 桌面常驻挂件：鼠标指针下方悬挂一个晴天娃娃（当前用 🧸 emoji 占位），
娃娃跟随鼠标移动并产生物理摇晃效果。

**这不是物理模拟器，是桌面玩具。** 手感优先于物理正确性：
好看、顺手、不碍事。允许为了观感引入「反物理」的作弊参数。

- 项目目录：`F:\study\DeepSeekHarness\test_1\晴天娃娃\v0\`
- 技术栈：Electron（透明置顶全屏窗 + Canvas 2D 渲染）
- 沟通约束：**用户不懂英文，所有回复必须用中文**

## 三、用户对 R13 / R14 / R15 的原始表述（m02010）

> **修改：**
> 1、绳子可以翻转到指针上方，这一块参考正常的牵引效果
>
> **确认点：**
> 1、两者都要，但是现在偏移相比图片旋转更不明显
> 2、更像真正的摆
> 3、暂时先不进行修改，等到后期优化
> 4、现在就行

逐条解读：

1. **R15 推翻了一个旧假设**：此前代码里有 `chain.maxAngle = 0.55`（31.5°）硬性限幅，
   目的就是「禁止绳子翻到指针上方」。用户现在明确说 **允许翻转**，要参考真实牵引绳
   （你拽着一根绳子的末端跑，绳子本来就可以被甩到支点上方再落回来）。
   → `maxAngle` 限幅必须去掉或大幅放开。

2. **R13 的「两者都要，但偏移比旋转更不明显」**：
   用户看到的是小熊几乎不倾斜、也几乎不位移，其中**位移的缺失更刺眼**。
   → 修复优先级：先让位置偏移明显，再让身体旋转跟随。

3. **R14「更像真正的摆」**：选了大摆幅、慢衰减，而不是「牵线木偶式」紧跟快归位。

4. **R17「3~5 节柔性延后」**：m02010 时节数和柔性调整冻结。**m01090 已解冻**——
   用户发现绳子变成了硬性钢体直棍，明确要求「更改为 3~5 个节点的软绳」。

5. **R16「绳长现在就行」**：60px 不改。

## 四之二、设置菜单的边界（R18）

用户要「可以手动调」，但**不是所有参数都该暴露给用户**。`settings-schema.js` 的 `FIELDS` 是唯一定义，
主进程会用同一份定义做 `sanitize`（钳制范围 + 按步长对齐 + 丢弃未知字段）。

| 分类 | 参数 | 理由 |
|------|------|------|
| **暴露给用户**（12 项） | `physics.gravity` / `chain.dampingPerSecond` / `physics.drag` / `physics.turbulence` / `doll.angleLimit` / `doll.bodyAngleTau` / `doll.heightRatio` / **`cursor.attachOffsetX`** / **`cursor.attachOffsetY`** / `chain.segments` / `rope.lengthRatio` / `rope.width` | 这些是"手感"，值变了只是观感不同，不会让模拟崩掉 |
| **故意不暴露**（数值安全阀） | `physics.fixedStep` / `maxStepsPerFrame` / `maxAccumulator` / `maxBend` / `bendIterations` | 调坏了只会更难用甚至数值爆炸，属于维护者参数，留在 config.js |

用户设置存 `%APPDATA%/sunny-doll/settings.json`，**不写回 `renderer/config.js`**：
config.js 是出厂默认值（要能进 git、要被 `rope.test.cjs` / `verify.cjs` 当基线），
打包成 asar 后也是只读的。点「恢复出厂默认」等于清空这个文件。

另：设置面板是**独立普通 BrowserWindow**，因为覆盖层是
`setIgnoreMouseEvents(true, {forward:true})` + `focusable:false` 的全透明窗（C1），
里面放不了任何可点的控件。面板打开期间覆盖层**仍然保持置顶**（任何时候都不离开
置顶带），只是把面板自己也提成置顶再 `moveTop()` 压到它上面；
关窗后把覆盖层 `moveTop()` 抬回置顶带最上面。

## 五、被用户明确否掉的方案（不要再提）

| 方案 | 否掉原因 | 来源 |
|------|----------|------|
| 网页版（浏览器里跑） | 用户选了 Electron 桌面悬浮层 | m00060 |
| 手绘 canvas 版娃娃 | 用户要 emoji 占位 | m00062 |
| 双摆物理 | 会像乱抽的皮鞭，视觉不可控 | 设计阶段 |
| 直接复用 npm `verlet` 库（subprotocol/verlet-js） | 无逆质量加权、无子步累加器、无帧率无关性，反而不能单独调「弹性」和「摇晃」 | m01020 调查 |
| `cursorSmoothing` 平滑跟随挂点 | 指针已到位、挂点还在半路蹭，被拉出几百 px 的假斜线 | m01770 |
| `_limitAngle` 按 tan 比例缩放水平偏移 | 每帧都触发，绳子被永久压扁，长度从 90 掉到 21.9 | 历史 |
| `monoDrop` 单调下垂投影（5d/5f） | 语义是「每个节点必须比上一个低 1px」，等于禁止翻到挂点上方，与 R15 直接冲突 | [09](09-物理评审与重构方案.md) |
| `minDroopRatio` 下垂下限投影（5e） | 绳长恒定时它给摆角设了硬上限 `acos(0.9)=25.8°`，是 R13 上不去的数学根因 | [09](09-物理评审与重构方案.md) |
| `_centripetal` 绕圈检测旁路 | 绕圈时 5d/5e 本来就被旁路，关掉作弊对绕圈数值**毫无影响**，纯属无效复杂度 | [09](09-物理评审与重构方案.md) |
| 给娃娃加独立钟摆自由度（Lc=43px） | 实测 body 冲到 173~180°，比现状更糟，必须自带角度软限幅 | [09](09-物理评审与重构方案.md) |
