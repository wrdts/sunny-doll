### 第十三版 · 第 18 轮 —— 挂饰库：名称 + 图片存项目 + 下拉联动（m05728）

用户三项需求：①「物理」页中把档位放置在页面内（选项卡下方）；②导入图片要输入名称、保存在项目中；③挂饰下拉以「图片+名称」为条目，切换时下方细节项联动。

| 决策 | 理由 |
|---|---|
| 图片复制进项目 `v0\assets\dangles\`（时间戳文件名防重名） | 原图可能被移动/删除；settings.json 只存项目内路径 |
| `dangleName` / `dangleList`（JSON 数组字符串）走 schema 的 STRINGS 通道 | 复用现有字符串 sanitize（maxLen 钳制），不新开 IPC |
| 挂饰下拉动态构建：`bear` + dangleList 索引 + `raw:<path>`（旧版未入库图兼容） | 换下拉 ≠ 改 schema 枚举，库内容随时变 |
| 下拉 change 同步写 dangle / image.path / dangleName 三键 | 联动是原子提交，不是三处各自触发 |
| 名称输入行只在「刚导入尚未入库」时显示（dataUrl 存在） | 入库后名称由下拉联动展示，避免界面常驻多余控件 |
| 档位条挪进 `</nav>` 之后（DOM 顺序即视觉顺序） | 不引入新的显隐逻辑，switchTab 原样工作 |

验证：13 JS `node --check` 全过、rope.test 17 组 ✓、verify 9 组 ✓；真机 E2E：布局 docH 763===winH、档位条仅物理页显示、导入→命名→入库→下拉联动→切回小熊→再切回全链路 ✓、settings.json 持久化 ✓。
### 第十四版 · 第 19 轮 —— 挂饰库管理：列表 / 重命名 / 删除（m05855）

| 决策 | 理由 |
|---|---|
| 库列表做成 import-row 之下的独立区块，每行 缩略图+名称输入+使用+删除 | 用户要求「增删」；重命名复用 change 事件，不弹编辑框 |
| 删除走新 IPC settings:delete-dangle，主进程校验 path.resolve 的目录必须等于 assets\dangles | 面板是不可信渲染层，绝不给它传任意路径删文件的能力 |
| 删除正在使用的挂饰 → 自动切回自带小熊并清 path/name | 不留悬挂引用（dangle=image 但 path 指向已删文件会回退 emoji，属隐式行为） |
| 重命名当前生效条目时同步 doll.dangleName | 下拉与细节行显示的是 dangleName，不同步会出现两个名字 |

验证：rope.test 17 组 ✓、verify 9 组 ✓；真机 E2E：加 2 条→重命名→使用→删使用中→回退小熊→删普通 全链路 ✓。
